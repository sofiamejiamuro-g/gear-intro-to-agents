The Agentic Era: From Answering to Acting

Hemos pasado de modelos que simplemente saben responder preguntas en lenguaje natural a sistemas de software que tienen autonomía para actuar, usar herramientas informáticas y resolver problemas de punta a punta.

Ayer • GenAI Clásica
💬

El Modelo Consulta (Answering)

Genera texto probabilístico basado en su entrenamiento previo. Está congelado en el tiempo y no tiene "brazos" para interactuar con sistemas reales.

// Prompt del usuario
"¿Cuáles son los pasos para reservar un hotel en París?"
→ Te devuelve un texto explicativo, pero TÚ debes hacer los clics.
Rol: Consultor estático Sin acciones en el entorno
Hoy • Agentic AI
🤖

El Agente Autónomo (Acting)

Tiene un objetivo asignado. Descompone la tarea, consulta APIs, captura errores y reacciona de forma dinámica hasta completar la misión.

// Meta asignada
"Encuentra hotel en París bajo presupuesto de $800 y agenda en Calendar."
→ Valida fechas, consulta Booking API, reserva y envía confirmación.
Rol: Empleado ejecutor Altera su entorno
💡 Regla de Oro: "Un chatbot genera secuencias de texto. Un agente utiliza herramientas para alterar su entorno."

¿Cómo Piensa un Agente? El Bucle ReAct en Vivo

01. Objetivo 1

Pregunta del Usuario

"¿Cuánto gastamos en licencias en la nube en Q3 y por qué subió tanto respecto a Q2?"
🎯 Meta: Recopilar datos y justificar anomalía
02. Thought (Razonar) 2

Inferencia Lógica

"No tengo la base de datos en mi memoria estática. Primero debo consultar la tabla financiera de BigQuery para Q2 y Q3."
🧠 Deducción: Requiere llamar herramienta SQL
03. Action (Herramienta) 3

Tool Call Estructurado

run_sql_query(
  table="costos_infra",
  quarters=["Q2","Q3"]
)
⚡ Ejecución: Conexión segura a BigQuery
04. Observation 4

Verificación & Respuesta

Retorno Real: Q2: $41,200 | Q3: $78,500.
Causa: Ingesta de 5 cluster de Kubernetes para nuevo modelo de IA.
✓ Resultado: Respuesta fundamentada con evidencia

Criterio de Ingeniería • Matriz de Decisión

¿Cuándo usar (y cuándo NO usar) un Agente?

¡No todo necesita un agente! Construir un agente para una tarea simple solo añade latencia y costos.

Caso 1 • Inferencia Pura Un solo paso

Resumir texto, clasificar correos o traducir

No requiere conectarse a otros servicios ni tomar decisiones sucesivas.

Usa API Simple LLM
Caso 2 • Pasos Fijos y Predecibles Reglas fijas

Si entra formulario → guardar en DB → mandar email

No hay ambigüedad ni incertidumbre; no uses IA para lo que resuelve un `if/else`.

Workflow Clásico
Caso 3 • Incertidumbre + Herramientas Alta variabilidad

Investigar anomalías contables o soporte adaptativo

Los pasos dependen de lo que descubre en el camino y debe interactuar con APIs externas.

4 Flashcards
Concepto #1

Tool Calling (Function Calling)

Toca para ver definición ↻

Capacidad del LLM de estructurar llamadas en JSON para invocar funciones, bases de datos o APIs externas.

✓ Fundamental para que el agente actúe
Concepto #2

Patrón ReAct

Toca para ver definición ↻

Ciclo iterativo: Thought (razonar) → Action (ejecutar herramienta) → Observation (evaluar resultado).

✓ Previene alucinaciones
Concepto #3

Grounding

Toca para ver definición ↻

Anclar y fundamentar las respuestas del modelo en fuentes de verdad verificadas (archivos de la empresa o Google Search).

✓ Cero inventos
Concepto #4

Human-in-the-Loop (HITL)

Toca para ver definición ↻

Diseño de seguridad donde el agente prepara y valida una acción crítica, pero exige confirmación humana para ejecutarla.

✓ Previene transacciones erróneas
